## Published package and release findings

These findings describe exact artifacts and release notes, not browser results. When checking an existing app, resolve its versions from the consuming workspace's lockfile and installed metadata, including symlinks and overrides. Inspect package `exports`, declarations, implementation, CSS, and dependency metadata; internal source paths are not public imports. The [original package map][original-packages] identifies the exact registry records and published files, which can also be inspected from a local installation/cache.

- **Skeleton:** In [`@skeletonlabs/skeleton-svelte@5.0.6`](https://unpkg.com/@skeletonlabs/skeleton-svelte@5.0.6/package.json), `dist/index.d.ts` and `dist/index.js` lead to the public root and the anatomy, snippet tuples, callbacks, and bindability. `/composed` is not exported. Follow the inherited Zag version for rendered tags, native/hidden inputs, event forwarding, and lifecycle. In [`@skeletonlabs/skeleton@5.0.6`](https://unpkg.com/@skeletonlabs/skeleton@5.0.6/package.json), inspect `src/index.css`, its utilities and `src/themes/*.css`; component styling is in the Svelte package's `dist/index.css`. Core exports the root, themes and metadata; presets come through core, not `/optional/presets`. The framework CSS superseded the old Skeleton distribution scan, not explicit Tailwind `@source` registration for shared app files.
- **Skeleton releases:** Comparison of the 5.0.4–5.0.6 npm artifacts, including [untagged component release 5.0.5](https://registry.npmjs.org/@skeletonlabs/skeleton-svelte/5.0.5), found manifest bumps and `useListCollection` returning `ListCollection<T, never>` in the declarations, with no caller redesign. The [5.0.6 CLI](https://github.com/skeletonlabs/skeleton/releases/tag/skeleton@5.0.6) did not replace manual migration. Common [5.0.3](https://github.com/skeletonlabs/skeleton/releases/tag/@skeletonlabs%2Fskeleton-common@5.0.3) fixed the navigation rail gap unit and [5.0.4](https://github.com/skeletonlabs/skeleton/releases/tag/@skeletonlabs%2Fskeleton-common@5.0.4) fixed Firefox QrCode output; both fixes are included in the later pin, not local workaround requirements.
- **Inherited Zag:** [Combobox 1.47.0](https://github.com/chakra-ui/zag/releases/tag/@zag-js%2Fcombobox@1.47.0) added result/no-result announcements and `loading`/`aria-busy`; Skeleton forwarded `loading` and translations. The recorded checks to retain were normal modal focus defaults, Escape and restored focus ([Dialog 1.45.0](https://github.com/chakra-ui/zag/releases/tag/@zag-js%2Fdialog@1.45.0), [1.47.0](https://github.com/chakra-ui/zag/releases/tag/@zag-js%2Fdialog@1.47.0)); rendered link boundaries ([Pagination 1.46.0](https://github.com/chakra-ui/zag/releases/tag/@zag-js%2Fpagination@1.46.0)); and keyboard exit ([Tabs 1.47.0](https://github.com/chakra-ui/zag/releases/tag/@zag-js%2Ftabs@1.47.0)). [Floating Panel 1.48.0](https://github.com/chakra-ui/zag/releases/tag/@zag-js%2Ffloating-panel@1.48.0) uses the positioner's `--z-index`; [Toast 1.47.0](https://github.com/chakra-ui/zag/releases/tag/@zag-js%2Ftoast@1.47.0) fixed focus and paused timers. These were inherited changes in Skeleton's wrappers, not separate application Zag imports.
- **Kit and adapter metadata:** [Kit 3.2.0](https://github.com/sveltejs/kit/releases/tag/@sveltejs%2Fkit@3.2.0) corrected initial `afterNavigate` route/params and `from`; not a guarantee at the 3.1 floor. In [Kit 3.4.0](https://github.com/sveltejs/kit/releases/tag/@sveltejs%2Fkit@3.4.0), `vite.customPreview: true` was an adapter capability paired with `configurePreviewServer`, not a Bun or application setting. [Adapter-auto 9.0.0](https://github.com/sveltejs/kit/releases/tag/@sveltejs%2Fadapter-auto@9.0.0) changed Cloudflare auto-detection to Workers rather than Pages. None of the preview runs established an adapter target.
- **Svelte and build tooling:** [Svelte 5.58.1](https://github.com/sveltejs/svelte/releases/tag/svelte@5.58.1) fixed native `bind:files` reset and `svelte/events` listener propagation; [5.59.1](https://github.com/sveltejs/svelte/releases/tag/svelte@5.59.1) fixed mount/hydrate types. [Vite 8.3.6](https://github.com/vitejs/vite/releases/tag/v8.3.6) fixed `#` subpath resolution in dependency optimization; applications still needed proper package import mappings. [Vite 8.3.8](https://github.com/vitejs/vite/releases/tag/v8.3.8) and [svelte-check 4.7.8](https://github.com/sveltejs/language-tools/releases/tag/svelte-check@4.7.8) needed no special configuration for the fixture; experimental async and `--tsgo` were not used.
- **Tailwind:** [4.3.4](https://github.com/tailwindlabs/tailwindcss/releases/tag/v4.3.4) fixed explicit symlinked `@source` watching and negated `.gitignore` scans, and stopped emitting CSS for invalid/empty modifiers. [4.3.5](https://github.com/tailwindlabs/tailwindcss/releases/tag/v4.3.5) fixed `color-mix` fallback and Oxide WASM scanning/install. These did not remove the need for stylesheet-relative shared sources where applicable or establish wider browser support.
- **Lucide and Lab:** [1.68.0](https://github.com/lucide-icons/lucide/releases/tag/1.68.0) renamed warning/alert icons; in [1.77.0](https://github.com/lucide-icons/lucide/releases/tag/1.77.0), `CircleExclamationPoint` / `@lucide/svelte/icons/circle-exclamation-point` is canonical and `circle-alert` remains an alias. [1.76.0](https://github.com/lucide-icons/lucide/releases/tag/1.76.0) expanded case conversion, but the exact public exports still decide slugs. As of [1.75.0](https://github.com/lucide-icons/lucide/releases/tag/1.75.0), automatic SVG hiding considers own, non-nullish `aria-*`, `role` or `title` values; a child snippet also disables auto-hiding. An undefined prop is not a name. [Lab 0.17.0](https://github.com/lucide-icons/lucide/releases/tag/@lucide%2Flab@0.17.0) kept the `pear` geometry; other icons graduated to core (e.g. in [Lab 0.15.0](https://github.com/lucide-icons/lucide/releases/tag/@lucide%2Flab@0.15.0)). For exact inspection, follow `@lucide/svelte@1.77.0`'s exports into `dist/lucide-svelte.d.ts`, `dist/types.d.ts`, `dist/Icon.svelte` and `dist/context.js`, and check `@lucide/lab@0.17.0`'s `dist/lucide-lab.d.ts` and `dist/esm/lucide-lab.js` for the actual named data and node shape. Lab is optional and separate from core icons.

## Source-backed research corrections

These are the corrections in the [pre-cutover source review][original-corrections], not claims taken on faith from secondary research. Search, Context7 and rolling pages served as discovery; the exact exports, declarations, implementation and generated CSS resolved disputed details.

- **Skeleton anatomy and state:** Accordion used `value: string[]`, `onValueChange` and `e.value`, not `open`, `onOpenChange` or `e.change`. The runtime exports were `Steps` and `QrCode`, not `Stepper` and `QRCode`. Switch was callable as `<Switch>`, not `<Switch.Root>` (see [5.0.1 anatomy](https://unpkg.com/@skeletonlabs/skeleton-svelte@5.0.1/dist/components/switch/modules/anatomy.d.ts)). Required provider IDs and element-snippet attribute forwarding mattered. `createToaster` created a store, not an enforced singleton: the checked composition used instance ownership and one renderer per store; shared layout context did not justify mutable per-user state in an SSR singleton.
- **Motion, styling and accessibility:** Reusable disclosures needed instance-safe IDs. Svelte's pinned motion implementation and Kit's client router were checked separately from the effect: skipped route decoration did not mean failed navigation. The source landmarks were `svelte/src/motion/spring.js`, `svelte/src/motion/tweened.js`, and `@sveltejs/kit/src/runtime/client/client.js` within the exact packages. Theme tokens, OKLCH and framework defaults did not prove contrast or keyboard access. Example presets and corner tokens were not automatically shipped utilities or global geometry; documentation navigation counts and preview/beta labels were not runtime export contracts. Editorial trend, universal timing, and browser-support claims were not retained as tested facts.
- **Lucide 1.61.0 source audit:** Public root named imports such as `Camera` were valid, and static per-icon defaults narrowed traversal without proving a universal speed or bundle-size advantage; a namespace runtime catalog is a different case. `lucide-svelte@1.0.1` was deprecated in favor of `@lucide/svelte`. The public `circle-alert` subpath worked at this pin; see the later naming change above. `size` and `strokeWidth` accepted `number | string` with defaults 24 and 2; CSS could override size, `color` defaulted to `currentColor` for SVG stroke, and raw `stroke-width` was accepted through rest attributes. `absoluteStrokeWidth` was deprecated, not removed: its numeric resize formula differed from `nonScalingStroke`'s per-shape `vector-effect`. At 1.61.0 the audit identified `aria-*`, `role`, `title` and a child snippet as inputs that suppressed automatic hiding; see the later nullish-value distinction above. Name the control, leave its icon decorative, and name meaningful standalone images explicitly. Generated component values were `LucideIcon` (`Component<LucideProps>`), not `typeof Icon`; generic `Icon` required custom data, with `iconNode: LucideIconNode[]` as one branch of its input union. This source-only review did not cover Lab runtime behavior; the later pass below did.
